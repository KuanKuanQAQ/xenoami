项目接手理解报告（2026 年 11 月 16 日）

> 本文保留接手时的状态快照。随后补齐的六篇提交说明见 [commits 索引](commits/README.md)，交接收尾进展见 [日志](log.md)。

这个项目要建立的是基于 Xenomai 4 EVL 的安全实时运行平台：让承担控制、采样等任务的可信实时程序，尽量不受普通 Linux 的错误或被攻破后的行为影响。原则的优先级一直明确：首先不能破坏实时性，其次缩小可信计算基，最后才是减少对 Linux、EVL、LKL 的改动。当前成果是能够运行的依赖拆分原型，完整安全隔离仍是后续目标。

我核对了会话决策、设计文档、提交和对应调用链；这不等于逐行审计三份内核树，或证明所有并发路径安全。测试数字来自已有记录，本次未重跑。

四个子模块分别保存改造内核 linux-evl、对照原版 linux-evl-orig、内核库 lkl 和用户库 libevl。Dovetail 管中断流水线与阶段切换，EVL 管调度、定时器和同步。EVL 线程仍对应 Linux 任务，可在 oob 与 inband 间切换；线程、地址空间、时间和生命周期是解耦难点。

最初路线是用 LKL 承接 Linux 调用，由 EVL 提供 host_ops。已实现十四个 helper，覆盖字符串、红黑树、位图和时间转换，早期迁移三十七处调用。LKL 按内核 ABI 编译，禁用 PIC、red zone 和浮点指令，处理特殊段与边界符号后参与宿主链接。目前只使用不依赖 LKL 运行环境的代码，完整 host_ops 和有状态服务尚未实现。

函数分级的本质是是否依赖执行环境。L0 只操作参数、调用方内存和只读常量，可以直接调用；L1/L2 涉及 LKL 状态或睡眠，需要正确的任务上下文和 CPU 所有权协议。单核 LKL 的竞争等待没有实时上界，所以既定规则是 oob 不进入这种上下文。即使看似简单的原子操作，也不能直接借用 LKL 的单核软件关中断实现。跨内核参数还必须检查结构布局及配置常量。

研究随后转向“先定归属，再定实现”。例如 Linux 等待队列里的任务不能靠 LKL 自己的调度器唤醒；把宿主队列传给 LKL，仍会依赖宿主的锁、指针和任务状态。可信性、代码来源、执行阶段是三个维度：Linux 来源的函数可以可信，EVL 文件里的通知处理函数也可以属于不可信侧；在 inband 创建实时对象的代码仍可能必须可信。

现在的方法从 oob 根出发，追踪读取的数据、写者及其依赖，构成可信闭包 Z，再寻找与不可信侧 z 的交集。边界应由依赖分析和截断得出，不能先按目录划定。约束是 Z 不依赖 z：既包括函数调用、值和指针，也包括锁、等待、资源耗尽。五种处理方式是私有副本、输入校验、只记录通知、拆分单侧所有权和消除不必要接口。门允许受控地修改可信状态，并非只能读取；关键在于对象身份、参数、状态转换和执行时间均受可信侧约束。

工具用 clang AST 提取字段读写、调用及数据流，传播闭包和分配单元归属。历史分析覆盖三十二个编译单元、八百五十五个函数，发现三十七个应移出的 Linux 成员和六十七个入口。全内核图和最小割也有探索，但依赖配置、间接调用近似与人工规则，尚非完备验收器。@TD 注释已撤回，历史输出不能当作当前版本的验证结果。

最成熟的公共改造是通知中继。原版通过 irq_work 从 oob 延后到 inband 中断上下文，需要睡眠时再交给 workqueue。新实现让可信侧只修改自身记录，挂入每 CPU 链表，并通过 Dovetail 投递合成中断；inband 处理函数经 take 门获得副本，自行唤醒、完成通知或排工作。done 门不再接受记录地址，而由可信侧保存当前记录。PENDING 合并重复通知，BUSY 标识执行中；普通对象停止发送后 drain，一次性销毁记录使用 ONESHOT。信号采用每线程固定记录，避免按次分配被拖延释放而耗尽可信堆。

这一机制覆盖线程切回 inband、内核线程启动、信号、monitor、observable、stax、延后工作、crossing 和 element 销毁。monitor 与 observable 已取消通知前窥探 Linux 等待队列，改为无条件登记。workqueue 的执行仍在不可信侧，无须为了替换第一跳而整体迁移。不过“核心已无 irq_work”只能限定范围：当前网络代码和 hectic 驱动仍有实际调用。tick 代理也属于另一条基础设施路径，会话明确它由其他人负责。

xbuf 是双向跨阶段字节流，proxy 则通过 inband 转发者访问普通 Linux 文件。最终方案将每个环拆成可信端、不可信端和共享区：可信端独立保存 fill、下标、预留量与等待队列，只发布进度，不回读共享计数作为权威。对端报告生产或消费数量，门按可信容量截断；地址由本侧下标计算。多调用者先预留、放锁拷贝，最后一个完成者统一提交，inflight 防止报告窗口内重复计算。

这里保护可信内存、时间和控制流，对端数据只能作为输入。对端停止服务时，主动选择阻塞通信的应用可能等不到结果。proxy 已删除 inband 读写及目标 oob_poll 转发；libevl 改用 oob I/O，未 attach 的标准输出直接写原流。早期 O_NONBLOCK 镜像和 proxy_bridge 方案已撤回；当前仍读取文件标志。

monitor 承担用户同步原语的内核后端，observable 提供发布订阅及健康事件。它们的 Linux 等待队列已移到单独结构，但 inband 等待仍有混合锁和混合状态操作。thread.c 则把 sysfs 的锁内读取与锁外格式化分开，约束初始 CPU 编号，并移走硬锁内打印；时钟睡眠的重启日期改存在线程私有状态。factory 已修复 flusher 线程指针和错误指针检查，GET_STATE 填错状态、attach 失败泄漏名字仍留待处理。

最新策略明确所有 EVL 线程可信，普通线程不可信。控制资格取决于是否 attach，而不是此刻是否处于 oob，所以暂时切回 inband 的 EVL 线程仍能管理其他实时线程。线程控制、TP/quota、时钟调整等入口已加入限制；有用户实时线程时停止核心返回忙。查询和主动开放的数据通道仍保留。谁可以 attach 尚未闭合，Linux 的信号、ptrace、亲和性和地址空间操作也绕过这些检查，因此目前不能保证恶意 Linux 下实时任务持续运行。

最大的剩余依赖是 oob 经 Linux fd 表、file、f_op 和 private_data 找对象。既定选择是可信域内的每进程句柄表，配合可信操作表、代数和名字解析，并接受 libevl ABI 改动。仅验证 Linux 返回的对象合法不够，因为它仍能替换为另一个合法对象。该方案目前只有设计。后续还包括拆 element 等嵌入对象、可信分配器与共享区生命周期、共享状态和用户地址审计、完整信任基清单、门调用风暴控制及物理隔离。

已有回归记录是七十七项 libevl 测试加管道压力测试，改前改后均通过七十四项；四项失败来自缺少 gdb 或未启用调度类。另开 TP/QUOTA 后，TP 测试通过，quota 精度约百分之一百零八，缺少同配置基线，不能直接归咎于虚拟机。构建仍需用 nokaslr 规避启动问题，测试配置关闭 IBT 和 CPU mitigations；功能回归不能替代最坏延迟测量或安全验证。

交接现场尚未收尾：内核四个主题改造和 libevl 两个改动已本地提交，父仓库仍指向旧版本；逐提交文档只有通知中继一篇，推送未确认完成。工具、补丁和构建目录被忽略，复现材料需要整理。后续应先固定基线和信任假设，再推进句柄表与生命周期拆分，扩大可检查的可信集合，最后落实隔离。
